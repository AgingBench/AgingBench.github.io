Thin trace? Boost with a synthetic probe

Your trace doesn't carry enough sessions or fired tests for a confident aging verdict. Run one AgingBench scenario as a probe against your live agent, then drop the resulting card here. The probe's headline + per-mechanism curve will appear alongside your telemetry numbers (in a new synthetic_probes block), so you see observational signal and controlled signal side by side without one overwriting the other.

  1. Install + run a probe (~$0.50–2 in API credit, 5–15 min wall on a Haiku-class model — depends on probes and retries). Pick a scenario from the injectable set: s1_research_literature, s2_lifestyle_assistant, s3_knowledge_base, s4_software_engineering, s6_naturalistic. Default SUT is the same Haiku-4.5 / lossy-compress one the Lite suite uses; swap for your own SUT YAML if you want the probe to run against your agent. 
    pip install "git+https://github.com/AgingBench/AgingBench.git@v0.3.0#subdirectory=prototype"
export ANTHROPIC_API_KEY=sk-ant-...
agingbench run \
  --scenario s2_lifestyle_assistant \
  --sut agingbench/registry/suts/haiku45/haiku45_lossy_compress.yaml \
  --sessions 8 --seeds 1 --card \
  --output ./probe_out
  2. Drop the probe card (probe_out/aging_card.json) below. Merging runs in your browser — no upload.

The merged card carries a new synthetic_probes block with the probe's headline + per-mechanism metrics tagged derived_from: synthetic_probe. Your observational signals stay where they are; the probe adds controlled signal alongside.

Get your trace in 60 seconds

    
Two paths are validated for v0.3.0: the native claude_code session files, and the generic JSONL shape (any custom format you can reshape into session_id + role + content + token fields). Five more adapters ship in the codebase — they parse correctly against our fixture tests, but the extraction recipes haven't been validated against current third-party SDKs. See the list below.


    


      

        

          
claude_code

          drop-in · verified
        

        
Files Claude Code already writes — no export step. Each .jsonl = one session; concatenate several so aging signal can be computed.

        
# macOS / Linux — bundle your 10 most recent sessions:
ls -t ~/.claude/projects/*/*.jsonl | head -10 | xargs cat > /tmp/cc_combined.jsonl

# Windows (PowerShell):
Get-ChildItem $env:USERPROFILE\.claude\projects\*\*.jsonl |
  Sort LastWriteTime -Desc | Select -First 10 |
  Get-Content | Set-Content $env:TEMP\cc_combined.jsonl

# Then drop the combined file into Step 1 and pick format=claude_code.

        
Contains: your prompts, agent replies, tool calls, token counts. PII patterns (emails, API keys, IPs) are auto-redacted before metric inference. Aging signal needs ≥3 sessions — picking a single .jsonl will trip the coverage: underpowered warning.

        
      


      

        

          
generic

          bring-your-own JSONL
        

        
Any JSONL with session_id, role, content, and token counts. The adapter aliases camelCase + snake_case field names.

        
{"session_id":"abc","role":"user","content":"hi",
 "input_tokens":42,"output_tokens":0,"timestamp":"2026-05-16T10:00:00Z"}
{"session_id":"abc","role":"assistant","content":"hello!",
 "input_tokens":0,"output_tokens":12,"timestamp":"2026-05-16T10:00:01Z"}

        
Bring whatever shape you have — best-effort field aliasing. Pick format=generic in the dropdown above.

      


    


    

      How much trace do you need? ≥3 sessions of ≥1 agent turn each is the floor for meaningful aging signal — below that the demo will flag coverage: underpowered and offer to augment with a synthetic probe.
      Privacy: all parsing happens in your browser via Pyodide. The trace never leaves your machine. The privacy scrubber redacts PII patterns (emails, SSN, card numbers, API keys, phone, IP) from prompt/response previews before inference; it does NOT scrub semantic content — review your trace if it contains proprietary prompts.
    


    

      
Other adapters (parse-tested, recipe pending)

      
Five additional format adapters ship in agingbench/telemetry/adapters/ and pass our fixture tests against bundled sample data. The extraction recipe for each — i.e. the literal command to dump a JSONL from your live deployment — depends on third-party SDK versions and hasn't been validated end-to-end in v0.3.0. If you already have a JSONL of the matching shape, drop it in Step 1 and pick the format from the dropdown — the parser handles it.

      
    
        
  • openai_assistants — Mixed thread.message / thread.run / thread.run.step objects. Recipe pending validation against OpenAI SDK 1.x; the exact field-shape from model_dump() may vary by SDK version.
    • 
        
  • openhands — OpenHands SDK event log (source, action, observation, llm_metrics). Recipe assumes a session path that varies by install method.
    • 
        
  • langfuse — Langfuse GENERATION spans (camelCase + snake_case both accepted). REST endpoint + filter syntax may drift across Langfuse releases.
    • 
        
  • langsmith — Routes through generic; you reshape LangSmith run JSON into the generic field tuple.
    • 
        
  • otlp — OpenTelemetry JSON spans (gen_ai.* and legacy llm.* namespaces). Exporter-specific (Phoenix, Honeycomb, Jaeger, otel-cli) — your wrapping may differ.
    • 
      

      
Adapter source + per-format input contract in agingbench/telemetry/adapters/. Promote one of these to the validated set by contributing a tested recipe against a live source — see Contribute.

    

  







  

    
For terminal users

    
The same pipeline is callable from your shell — no browser required. The fastest path is a one-liner:

    
pip install "git+https://github.com/AgingBench/AgingBench.git@v0.3.0#subdirectory=prototype"
python -c "from agingbench.telemetry import trace_to_card_v11 as f; \
import json; r = f(trace_jsonl='trace.jsonl', trace_format='claude_code', profile='code_assistant'); \
print(json.dumps(r.card['headline'], indent=2))"

    
Telemetry mode is the one path that needs no API key — it parses your trace locally and infers per-mechanism aging signals statistically. Or, for a fuller workflow (dumps both the headline and the per-mechanism trace_audit block):

    
pip install "git+https://github.com/AgingBench/AgingBench.git@v0.3.0#subdirectory=prototype"

from agingbench.telemetry import trace_to_card_v11

result = trace_to_card_v11(
    trace_jsonl="path/to/your_trace.jsonl",
    trace_format="claude_code",          # or: openai_assistants, openhands, langfuse, langsmith, otlp, generic
    profile="code_assistant",            # or: generic
    extract_outcomes=["claude_session_flags", "record_patterns"],
)
print(result.card["headline"])
print(result.card["trace_audit"])

    
A first-class agingbench telemetry CLI subcommand wrapping the above lands in v1.1. See the telemetry reference in the docs for the format/profile/extractor catalogue and the AgingCard schema reference for the full output shape.

  







  

    
How it works

    
Telemetry mode is the inverse of scenario mode. Instead of running constructed probes against your model, it parses a JSONL trace that your deployed agent already produced and infers per-mechanism aging signals statistically:

    
    
      
  • Compression — context-saturation rate, self-contradiction across sessions, fact-density slope, context-noise ratio trajectory
    • 
      
  • Interference — tool-call distribution KL drift over sessions, goal-anchor drift trajectory
    • 
      
  • Revision — user-correction repetition rate, stale-value citation rate, per-session violation trajectory
    • 
      
  • Maintenance — model-swap / context-reset shock detection, pre/post deltas, intervention-rate trajectory
    • 
    

    
Every block carries a coverage.verdict field (strong / adequate / weak / underpowered / no_test_fired) so a low score can't be confused with "agent didn't age." Trajectories also ship with a saturation-aware verdict (rising_degradation, floor_healthy, etc.) — see the telemetry reference for the full verdict glossary, and agingbench/telemetry/inference/ in the repo for the per-mechanism math.
